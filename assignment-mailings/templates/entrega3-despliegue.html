1. Actualicen desde upstream

El repositorio de su grupo es {{repo}}. El código base trae las diecisiete épicas del enunciado implementadas en el backend. 

git checkout -b mezcla-entrega3
git fetch upstream
git merge upstream/main --allow-unrelated-histories

La bandera no es opcional. Los repositorios se crearon desde un template y no como fork, así que si su grupo nunca mezcló upstream, Git responde fatal: refusing to merge unrelated histories y no empieza siquiera. Si ya mezclaron antes, la bandera se ignora sola. En una rama, no sobre main.

Antes de mezclar, lean la sección de migraciones del enunciado. Si escribieron migraciones propias en la entrega 2, la mezcla deja dos cabezas de Alembic y el backend no arranca. El enunciado explica cómo encadenarlas, y hay dos cambios de contrato en la API que no aparecen como conflicto de Git.

El enunciado está en docs/entrega3.md. El contrato completo de la API, organizado por épica, está en backend/docs/api.md: cada una de las diecisiete dice qué endpoints la sirven y qué decisiones del backend cambian lo que tienen que escribir en el cliente.

3. Configuren el repositorio

En Settings → Secrets and variables → Actions de {{repo}}. Son dos pestañas distintas y cada dato va en la suya.

Pestaña «Variables» — no son secretas:

GROUP_ID {{group_id}}
HOST_PORT {{host_port}}
PUBLIC_ORIGIN {{public_origin}}
SEED_DEMO_DATA true

Pestaña «Secrets» — el primero se los damos nosotros:

DATABASE_URL

{{database_url}}

Los demás los generan ustedes:

  • JWT_SECRET — una cadena aleatoria larga, propia del grupo. El backend se niega a arrancar con el valor de desarrollo cuando corre en producción.
  • VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY y VAPID_SUBJECT — las mismas de la entrega 2. Sin ellas el despliegue funciona, pero nadie recibe notificaciones.
  • VITE_GOOGLE_MAPS_API_KEY — restringida por referente HTTP a {{public_origin}} y a localhost. Sin ella el mapa no carga.

El detalle de cada variable y cada secreto, y qué hacer cuando algo falla, está en DEPLOY.md, en la raíz del repositorio.

4. Desplieguen

Cada push a main dispara el despliegue. También pueden lanzarlo a mano desde la pestaña Actions con Run workflow, que es lo recomendable la primera vez, cuando aún no han empujado nada.

Con el despliegue en marcha, comprueben que responde:

curl -i {{public_origin}}/healthz

Si el workflow falla en el paso «Comprobar la configuración», el mensaje nombra qué variable o secreto falta.
